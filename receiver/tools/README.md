# CSI CSV 파일 설명

50hz 로 1초 50패킷이고 10초 수집함  
손실은 안테나 방향(금속판을 마주보면 더 잘나옴) , 채널 혼잡이 원인.
이 외 시리얼을 csv 로 만들때 병목? X  
receiver 큐 넘침? X   
기존 idf 모니터 프로세스가 이미 시리얼을 보고있어서 Ctrl ] 로 끄고 쉘로 읽어야 전부 다읽음 O

측정 환경은 120cm 간격을 두고 칩을 책상위에 천장을 본 상태로 눕혀서 측정(안테나가 천장을 보는 방향, 오른쪽이 수신 왼쪽이 송신기)  
본인은 모서리에 붙어 책상에 않아서 3분간 측정  
자세는 의자에 기대서 고정했고 자연스러운 호흡만 하였음  
칩 사이의 정중앙에서 앉아있었고 흉곽이 칩의 직선경로에 걸치는 자세로 측정.

`seq` — 패킷 번호  
보낼때 순서대로 바디에 담아 보냄,  
이걸로 손실됐는지 파악 가능.

`lost` — 지금까지 잃어버린 패킷 수 (누적)  
seq 보고 사라진 패킷 누적 계산

`ts_us` — 받은 시각 (마이크로초)  
부팅부터 마이크로초 단위로 시각을 잼

`rssi` — 신호 세기 (dBm)  


`first_word_invalid` — csi 첫 4바이트 무효 여부  
1이면 수신 오류로 4개 값이 쓰레기값이라 버려야 함, 0이면 정상  
해당 4개값은 서브캐리어 0,1번의 값들로 0번 서브캐리어는 DC 성분이라 원래 안쓰고  
1번 서브캐리어를 쓸지 말지를 결정하게됨

`len` — csi 값 개수  
csi 필드에 숫자 몇 개 들었는지, 지금은 항상 256

`csi` — 채널 상태 정보 원본  
숫자 256개를 공백으로 구분해서 한 칸에 넣음  
2개씩 묶어서 서브캐리어 1개 (허수부, 실수부 순서)  
앞 128개는 L-LTF, 뒤 128개는 HT-LTF (펌웨어에서 둘 다 켜고 따로 받게 해둠)  
각각 서브캐리어 64개, 순서는 0 ~ 31, -32 ~ -1    

의미 없는 값 위치 (값 위치는 0부터 셈)
- 0 ~ 1 : L-LTF DC (2 ~ 3 은 경우에따라)
- 54 ~ 75: L-LTF 가드 (옆 채널이랑 안 겹치게 비워둔 자리, 항상 0)
- 128 ~ 129: HT-LTF DC (채널 한가운데라 안 씀, 항상 0)
- 186 ~ 199: HT-LTF 가드 (항상 0)
